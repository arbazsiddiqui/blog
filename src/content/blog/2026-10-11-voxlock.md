[VoxLock](https://huggingface.co/arbazsiddiqui/voxlock) keeps the caller's voice and removes the other voices in the room before speech-to-text hears them. It is made for voice agents: one input, the call audio, and it picks out the caller by itself.

It has the lowest word error rate on the Krisp Voice Isolation Benchmark of every model tested, paid or open: 4.95%, with 0.11 background words leaked per minute. Below, it runs in your browser.

## How it works

VoxLock is a causal band-split RNN target-speaker extractor, 27M parameters, fine-tuned from the [REAL-TSE challenge baseline](https://github.com/REAL-TSE/wesep-real-tse). It takes the loudest 3 seconds in the first 15 seconds of the call as the caller's voice sample. The sample becomes frame-level speaker features that each frequency band attends to, and the network predicts a mask over the call's spectrogram that keeps the matching voice. The [paper on arXiv](https://arxiv.org/abs/2610.40727) has the full method and results.

It streams with 24 ms of algorithmic latency, plus the chunk. With the default 8-bit model on one CPU thread of a Google Cloud Intel Xeon, a live call takes 77% of a core with 40 ms chunks and 61% with 80 ms chunks, so one vCPU runs one call. On an NVIDIA L4 GPU, a whole recording runs 40 times faster than real time.

## Performance

One live call through `VoxLock.stream` with the default `int8` model on one CPU thread: onnxruntime 1.31.1 on a Google Cloud g2-standard-8 (Intel Xeon @ 2.20 GHz), 60 seconds of AMI meeting audio.

| Chunk | CPU per call | Real-time factor |
|---|---|---|
| 20 ms | 110% of a core | 1.10 |
| 40 ms | 77% of a core | 0.77 |
| 80 ms | 61% of a core | 0.61 |

Below 1 keeps up with the call. 20 ms chunks keep up on two threads (0.86). The model has 27M parameters and 24 ms of algorithmic latency, plus the chunk. On the same machine's NVIDIA L4 GPU (`fp32`, CUDA), a whole recording runs 40 times faster than real time.

### Precisions

The ONNX model comes in four precisions, all in the [Hugging Face repository](https://huggingface.co/arbazsiddiqui/voxlock/tree/main/onnx/v2). Choose with `VoxLock(precision=...)`, `voxlock --precision ...` or `VoxLockFilter(precision=...)`.

| Precision | Quality | Files | Download | Word error rate % | Background words leaked / min | CPU per call, 20 ms chunks |
|---|---|---|---|---|---|---|
| `int8` (default) | 99.8% | `enroll.onnx`, `chunk_int8.onnx` | 74 MB | 5.11 | 0.12 | 110% |
| `int8-full` | 99.1% | `enroll.onnx`, `chunk_int8_full.onnx` | 71 MB | 5.85 | 0.04 | 110% |
| `fp16` | 100%\* | `enroll_fp16.onnx`, `chunk_fp16.onnx` | 47 MB | 4.95\* | 0.11\* | 163% |
| `fp32` | 100% | `enroll.onnx`, `chunk.onnx` | 94 MB | 4.95 | 0.11 | 165% |

Quality: the share of `fp32`'s correctly transcribed words each precision keeps, on the 265 Krisp recordings. CPU per call: one live call on one thread of the Xeon in [Performance](#performance).

\* `fp16` matches `fp32` to over 70 dB, so it carries the `fp32` scores. The browser demo uses it.

## Training

Four stages on a single NVIDIA L4, 9,200 steps in total:

1. **Simulated calls:** LibriSpeech callers mixed with one or two background talkers in simulated rooms, a quarter of them telephone band, with the voice sample cut from the mix.
2. **Real crosstalk:** AMI headset recordings from 40 meetings, where the other people in the room bleed into the wearer's microphone.
3. **Long calls:** 30-second clips where the caller talks throughout.
4. **Rooms and distances:** callers close to or far from the microphone, background voices dry or in the room, and real room noise.

## Use it

For voice agents: a [Pipecat](#pipecat) audio filter, a [LiveKit](#livekit) Agents plugin, and [sherpa-onnx](#sherpa-onnx) in C++. For files and your own streaming loop, read on.

```bash
pip install voxlock
voxlock call.wav -o caller.wav
```

Any sample rate, mono or stereo. The 74 MB model downloads on first use, or ahead of time with `voxlock download`.

```python
import voxlock

vl = voxlock.VoxLock()                     # precision="fp32" for the benchmarked model
call = voxlock.load_audio("call.wav")      # 16 kHz mono float32
caller = vl.isolate(call)                  # same length as the input
```

`isolate` takes the caller's voice sample from the first 15 seconds of the call. Pass `sample=` (3 seconds or more) to choose it yourself.

### Streaming

Push the call in as it arrives, as 16 kHz float32 chunks of any size. Each `push` returns the isolated audio that is ready, about 24 ms behind the input.

```python
vl = voxlock.VoxLock(threads=1)
stream = vl.live()                         # finds the caller by itself
for chunk in call_audio:                   # e.g. 40 ms = 640 samples
    send(stream.push(chunk))
send(stream.flush())                       # at the end of the call
```

`live()` passes audio through until it has heard 3 seconds of the caller, then isolates. On the 265 Krisp recordings it scores 5.15% word error rate (4.95% on whole files).

If you already have a sample, from earlier in the call or from a previous call, isolation starts with the first chunk:

```python
stream = vl.stream(sample)                 # about 3 s of the caller, 16 kHz mono
```

On one CPU thread it keeps up with chunks of 40 ms or more (see [Performance](#performance)).

### Pipecat

```bash
pip install "voxlock[pipecat]"
```

```python
from pipecat.transports.base_transport import TransportParams
from voxlock.pipecat import VoxLockFilter

params = TransportParams(audio_in_enabled=True, audio_in_filter=VoxLockFilter())
```

Passes audio through until it has heard 3 seconds of the caller, then isolates (`voice_sample=` isolates from the start). Any transport rate, Twilio's 8 kHz included. One thread, 61% of a CPU core, 184 ms delay at 16 kHz; `chunk_ms=40` gives 104 ms for 77%. Example: [examples/pipecat_bot.py](https://github.com/arbazsiddiqui/voxlock/blob/main/examples/pipecat_bot.py). Tested with Pipecat 1.15.0.

### LiveKit

```bash
pip install "voxlock[livekit]"            # or: pip install livekit-plugins-voxlock
```

```python
from livekit.agents import room_io
from voxlock.livekit import VoxLockFilter   # or: from livekit.plugins import voxlock; voxlock.VoxLockFilter()

await session.start(
    agent,
    room=ctx.room,
    room_options=room_io.RoomOptions(
        audio_input=room_io.AudioInputOptions(sample_rate=16000, noise_cancellation=VoxLockFilter()),
    ),
)
```

One filter per session. Passes audio through until it has heard 3 seconds of the caller, then isolates (`voice_sample=` isolates from the start). One thread, about 68% of a CPU core, 124 ms delay at 16 kHz. Call `preload()` in your prewarm function; `download-files` fetches the model. Example: [examples/livekit_agent.py](https://github.com/arbazsiddiqui/voxlock/blob/main/examples/livekit_agent.py). Tested with livekit-agents 1.8.10.

### sherpa-onnx

Built into [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)'s speech denoisers from 2.0.1, in C++. Models from [this release](https://github.com/arbazsiddiqui/voxlock/releases/tag/sherpa-onnx-models), then:

```bash
sherpa-onnx-offline-denoiser \
  --speech-denoiser-voxlock-enroll-model=voxlock_enroll.onnx \
  --speech-denoiser-voxlock-chunk-model=voxlock_chunk_int8.onnx \
  --input-wav=call.wav --output-wav=caller.wav
```

`sherpa-onnx-online-denoiser` streams with the same models; `--speech-denoiser-voxlock-voice-sample=caller.wav` sets the voice sample.
